## Report on task 11: 2Captcha adapter + facade

### Spec/ADR amendments

- [acted] ADR-0076 2Captcha table diverges from live API docs on
  three wire details; implemented per live docs: (1) image extras map
  `min_len`→`minLength`, `max_len`→`maxLength` (table said
  `min_len`/`max_len`); (2) `lang` does not exist on modern
  ImageToTextTask/TextCaptchaTask — owner decision 2026-08-27: replaced
  with `language_pool` (`en`/`rn`) riding the envelope-level
  `languagePool` field; `lang` dropped; architecture §2 rows corrected;
  (3) reCAPTCHA v3 enterprise is not a separate task type on 2Captcha:
  it is `isEnterprise: true` inside `RecaptchaV3Task[Proxyless]` (the
  table's `RecaptchaV3EnterpriseTask` naming comes from Anti-Captcha).
- [needs-decision] Universal kind bases type `data_s` as
  `Mapping[str, str]`, but the provider's `recaptchaDataSValue` is a plain
  string token. Current behavior: non-enterprise collapses a single-pair
  mapping to its value (`{"s": tok}` → `"tok"`) and raises
  InvalidChallengeError for multi-entry mappings; enterprise merges the
  mapping into `enterprisePayload`. Consider retyping the base field to
  `str | None` in a follow-up ADR (touches all providers + tests).
- [acted] Report good/bad for 2Captcha IS available on the modern JSON API
  (`POST /reportCorrect|/reportIncorrect`, `{clientKey, taskId}` →
  `{errorId, status:"success"}`), verified live and via competitor repos:
  `python-rucaptcha` uses exactly this; the official `2captcha-python`,
  `unicaps`, and `anycaptcha` are legacy-protocol-only and mislead here.
  Adapter implements both pairs as supported (ADR-0068 pairs, default
  endpoints). No ADR change needed — matches ADR-0073 vocabulary.
- [needs-decision] ADR-0072 project affiliate id is still unregistered;
  `_PROJECT_SOFT_ID = None` in `provider/twocaptcha/adapter.py`, so
  `referral=True` currently embeds nothing (owner confirmed "nothing yet").
  Register an id at 2captcha.com/software and set the constant.

### Tooling/process

- Zero-arg `super()` breaks inside `__post_init__` of frozen+slots
  dataclasses after dataclass class recreation ("obj is not an instance or
  subtype of type"); call the parent method explicitly
  (`ImageChallenge.__post_init__(self)`).
- Pyright strict rejects TypeVars appearing once in a signature
  (reportInvalidTypeVarUse) where mypy accepts them; the witness-parameter
  pattern (explicit `result_type=` kwarg driving inference) satisfies both
  checkers without runtime cost or casts at call sites.
- Live provider docs (2captcha.com/api-docs) expose full request/response
  tables per endpoint and beat SDK archaeology for JSON-API fidelity;
  vendor SDKs in `var/repo/` largely still speak the legacy protocol.
