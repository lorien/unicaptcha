## Report on task 16: Engine tests (injectable clock)

### Tooling/process

- [open] The `Clock` protocol's `sleep` is sync and used only by the sync
  engine; the async engine keeps `asyncio.sleep`. A future async-fake-clock
  would need an async sleep hook and would still face the `asyncio.timeout`
  real-time budget (asyncio.timeout is event-loop-time, not fake-monotonic).
  If fully-instant async timeout tests are ever wanted, that needs a loop-time
  injection seam, not just a clock.
- [acted] Sync engine sleeps are now ≤0.05 s slices through the injectable
  clock; close-wakeup latency is bounded by one slice instead of an
  instant `shutdown.wait` wake. ADR-0033's "at most one in-flight HTTP round
  trip" guarantee is unaffected (checkpoints unchanged).
