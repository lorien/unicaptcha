## Report on task 12: Anti-Captcha adapter + facade

### Spec/ADR amendments

- [needs-decision] Text row `lang→lang` shipped unverified: the official
  SDK has no TextCaptchaTask module and the apidoc page is JS-rendered
  (webfetch returns marketing content only). Verify against the live API
  at golden-payload time (task 17); if the field is inert, align with the
  image row's `language_pool→languagePool` pattern.
- [needs-decision] GeeTest v3 solution keys: the SDK returns the whole
  `solution` dict unwrapped; analysis recorded `challenge/$challenge/
  captcha_output/seccode`, which does not map cleanly onto our
  `GeeTestV3Solution{challenge,validate,seccode}`. Adapter maps the
  canonical `challenge/validate/seccode` keys; confirm against a live
  response before task 17's golden fixtures.
- [needs-decision] Kind-aware reporting: Anti-Captcha's four report
  endpoints are per-kind, but `TaskRef` carries no kind and the engine
  posts to a single fixed `endpoints.report_*` path. Report pairs are
  default-off this task (owner decision). A future ADR could extend the
  adapter contract (e.g. kind-carrying report API or per-kind report
  dispatch) to enable them.
