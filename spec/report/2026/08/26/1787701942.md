## Report on task 3: Error hierarchy
State: new

- The 1:1 `ErrorKind`-to-class invariant (ADR-0009) is now pinned by a
  data-driven table test (`ErrorKind` enum member -> exception class,
  instantiate and assert `.kind`). This is exactly the ADR-0019 "error
  mapping tables" commitment style and will catch drift if a future ADR
  adds/removes a kind. Consider keeping the table in one module so
  adapter tests (task 17) can reuse it.
- Several "requirements" in task 3 are behavioral and cannot be encoded in
  the classes themselves: the `raise ... from cause` chaining discipline,
  wrong-provider `TypeError` pre-flight (ADR-0045), and malformed-response
  `ProviderError` with `__cause__` (ADR-0040). They are documented in the
  errors.py docstring and will be enforced in tasks 7-10. No test can
  verify them here; the adapter/engine tasks should carry those tests.
- Exception pickling is a non-goal: the keyword-only state (`raw_response`,
  `kind`) is not reconstructible through `Exception.__reduce__`, so a
  pickled error would lose `raw_response`. No ADR requires picklable
  errors (the picklable-vocabulary requirement covers the frozen-data
  models, task 2). Flagging so it is a known, deliberate absence rather
  than a surprise.
- `EmptySolutionError.__init__` calls `UnicaptchaError.__init__` directly
  (not `super()`) because it bypasses `ProviderError`'s hardcoded kind
  while staying a `ProviderError` subclass — worth a comment in the file
  if it looks odd to future readers (it is already explained in the
  docstring).
- Root `__all__` growth is mechanical; the RUF022 sort is now enforced and
  the root-export test guards every error class. No further action.
