## Report on task 1: Toolchain + package scaffold
State: new

- Two toolchain config gaps surfaced on the "empty tree" that the spec
  did not anticipate: (a) ruff 0.11+ formats Python code blocks inside
  `.md` files, so `ruff format --check .` flagged the deliberately
  hand-aligned ADR/README pseudo-code for a noisy rewrite — fixed by
  excluding `*.md`/`*.markdown` from `[tool.ruff.format]`; worth
  recording as a deliberate toolchain decision in ADR-0019. (b) bare
  `pyright` (no args) analyzes the whole workspace including the
  gitignored `var/repo/` competitor checkouts — scoping
  `[tool.pyright] include = ["unicaptcha"]` fixed a 19k-error cascade.
  ADR-0019/ADR-0004 should note that both checkers are scoped to the
  `unicaptcha` package only.
- `uv run pyright` and `uv run mypy unicaptcha` are asymmetric in scope
  (pyright = whole tree, mypy = package). If the intent is
  "checkers run on the package", consider making both invocations
  explicit in testing.md (e.g. `pyright unicaptcha`) so the scope lives
  in the documented command, not only in pyproject config.
- `var/` holds third-party source checkouts for analysis; it is
  gitignored but still scanned by default pyright/rg/grep. Consider a
  small note in bootstrap.md or a pyproject top-level `exclude` so future
  tool additions don't trip over it again.
- pytest errors out (exit 4) if `testpaths = ["tests"]` exists but the
  directory does not — the scaffold needed a minimal smoke test before
  any real test work (task 15) to make CI green. Worth a line in
  testing.md or bootstrap.md noting the `tests/` dir + at least one
  collectable test is a baseline prerequisite.
- CI uses `astral-sh/setup-uv@v5` with `python-version` per matrix cell;
  the informational 3.14t job depends on setup-uv supporting the `t`
  suffix. If 3.14t install ever flakes, the job is `continue-on-error`
  so it will not block — no action needed, just awareness.
- Coverage presentation and any future threshold were explicitly left
  out of CI and recorded as deferred #21 (ADR-0047 keeps pytest-cov
  informational). Task 18 is already scoped to the release-consistency
  tag job (ADR-0021/0022), so nothing further needed there.
