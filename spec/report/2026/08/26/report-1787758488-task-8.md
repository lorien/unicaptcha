## Report on task 8: HTTP layer

### Spec/ADR amendments

- [open] architecture.md §1 layer table lists "retry policy" as part of
  the HTTP layer row, but the owner decided the layer is transport-pure
  with retry in the engine (task 9). Worth a wording touch ("httpx wiring,
  per-request User-Agent, pool" — drop "retry policy") so the diagram
  matches the implemented split.

### Future-task notes

- [open] Engine (task 9) owns retry/backoff: full-jitter backoff, retryable
  vs fail-fast classification via the chained httpx exception —
  `httpx.ConnectError`/`ConnectTimeout` (pre-send, safe) vs
  `ReadTimeout`/`ReadError` (after-send, fail-fast) per ADR-0011. The
  transport raises `NetworkError` with the httpx cause; the engine
  inspects `exc.__cause__`.
- [open] Engine builds URLs via `join_url(base_url, endpoint)` (ADR-0073)
  and decides HTTP-status policy (429/500/503 retry, 502/504 fail-fast).
- [open] Clients (tasks 9/10) pass `network=`/`network_client=`/`user_agent=`
  through to the transports; the mutual-exclusion `InvalidConfigError`
  already lives in the transport constructor (single enforcement point).
