## Report on task 5: Challenge kind bases (with task 6: Solution kind bases)
State: new

- **Tasks 5+6 executed as one folded unit** (owner-approved): the
  challenge->solution type link and the symmetric taxonomy make them
  inseparable; the link is real rather than a placeholder. Recommend the
  spec/plan note this coupling so future sessions don't split them again.
- **CPython bug worked around**: `super().__post_init__()` inside a
  `slots=True` dataclass `__post_init__` raises `TypeError: super(type,
  obj): obj is not an instance or subtype of type`. Reproduced on 3.13;
  this affects any slots dataclass, so kind bases must NOT chain the root
  guard via `super()`. Resolution: each solution kind calls
  `guard_abstract(self, <Kind>)` directly (no `super()`); the root
  `BaseSolution`/`BaseChallenge` guards run through their own
  `__post_init__`. Worth recording so task 11-14 provider subclasses don't
  reintroduce `super().__post_init__()`.
- **pyright `reportPrivateUsage`** forced the shared guard into
  `_internal/taxonomy.py` (a module-private function cannot be imported
  across public modules). Cleaner than a per-file duplicate; note it as
  the canonical home for any shared "abstract base" machinery.
- **mypy narrowing in ImageChallenge**: the `Path` branch needed a separate
  `path` variable (f-string on the reassigned `body` triggered
  str-bytes-safe) and `cast(bytes, self.body)` in `__repr__` (mypy cannot
  see that `__post_init__` normalized the field). This is the documented
  ADR-0065 "always stores bytes" contract; the cast is the honest
  encoding of it.
- **Type pin for GeeTest v4**: `gen_time` typed `str` (and all five answer
  fields required, no None defaults). Adapter tasks (11-14) should confirm
  providers return it as a string; if a provider returns an int/float it's
  a small per-provider subclass adjustment, not a base change.
- **Provider extras and proxy/worker-context deliberately absent from kind
  bases** (ADR-0012/0069/0076): they land on the provider subclasses in
  tasks 11-14. Task 5's kind bases stay universal-only. The
  `solution_type` link plus the kw_only field pattern (proven by the
  inheritance-wart test) is exactly what those tasks build on.
- **Root `__all__`** grew by 20 names (10 challenge + 10 solution kinds);
  the RUF022 sort + root-export test keep it mechanically consistent. No
  further action.
