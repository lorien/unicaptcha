## Report on task 2: Core models and public types
State: new

- **Cross-task dependency, resolved by pull-forward**: `types.py` needs
  `InvalidConfigError` (task 3) and `BaseSolution` (task 6). I created
  minimal roots now (`errors.py` with `ErrorKind`+`UnicaptchaError`+
  `InvalidConfigError`; `solution/base.py` with the abstract root) and tasks
  3/6 extend them. Worth encoding this expectation in the plan/spec so
  future sessions know the ordering is deliberately loose for these two
  modules.
- **ADR-0067 deviation: `TaskTicket` non-constructibility.** After review
  with the owner, the "not user-constructible" requirement is expressed as
  documentation ("created by submit(); do not construct") rather than a
  runtime guard. Python cannot actually prevent construction of a concrete
  public dataclass; a private-sentinel kwarg is a footgun marker that adds
  API noise for no real safety, and the "same spirit as solution bases"
  pattern doesn't map onto a concrete leaf class. Suggest a one-line
  ADR-0067 amendment ("enforced by documentation and provenance, not by a
  runtime guard").
- **ADR-0014 deviation: strict `SecretStr` equality.** Per owner decision,
  comparing `SecretStr` to anything other than `SecretStr` raises
  `TypeError` (a silent `False` reads as "values differ", which is a trap);
  `None` compares `False`. Consequence worth documenting: because
  `hash(SecretStr)` hashes the wrapped value, probing a dict/set keyed by
  `SecretStr` with a plain `str` hits the same hash bucket and raises
  `TypeError` rather than a silent `KeyError` — consistent with the strict
  boundary. Suggest amending ADR-0014's "value equality" line to pin the
  TypeError semantics.
- **`Proxy` field order** deviates from the architecture.md sketch (`kind`
  first): dataclass default-ordering rules require `kind` (defaulted) to
  follow the required `host`/`port`. Sketch is illustrative; keyword usage
  is unaffected. No ADR change needed, but a reader comparing the two may
  blink.
- **slotscheck and Enum**: `TaskStatus`/`ProxyKind`/`ErrorKind` passed
  slotscheck without special handling — no config needed.
- **`slots=True` + frozen pickling** verified working on 3.13 for
  `TaskRef`/`TaskTicket`/`TaskResult`/`TaskStatusResult`/`SecretStr`; the
  3.11 floor relies on the slots-dataclass `__getstate__`/`__setstate__`
  support added in 3.11 — CI matrix will confirm on 3.11.
- **Merge helper placement**: `_internal/config.py` holds a pure
  `merge_configs` used later by the engine (task 9). Architecture.md's
  `_internal/` listing ("engine, http layer implementation, clock,
  scrubbing") could mention config resolution as a member.
