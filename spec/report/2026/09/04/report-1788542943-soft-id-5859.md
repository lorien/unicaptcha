## Report on task: Register the project 2Captcha/RuCaptcha soft_id (5859)

Ad-hoc owner task (not a plan record): integrate the real affiliate id
for the 2Captcha/RuCaptcha service.

### Done

- `unicaptcha/provider/twocaptcha/adapter.py`: `TwoCaptchaAdapter` now
  declares `project_soft_id: ClassVar[int] = 5859` (ADR-0072). The
  default `referral=True` therefore embeds `"softId": 5859` in every
  2Captcha/RuCaptcha payload; RuCaptcha inherits it via the same adapter
  with a `base_url` override. Anti-Captcha/CapMonster keep `None` (no
  registered id — `referral=True` embeds nothing, unchanged); Capsolver
  already returns `None` (no affiliate field).
- Tests updated for the new default:
  - `tests/test_twocaptcha.py`: `test_payload_envelope_and_softid`
    default case asserts `softId == 5859`.
  - `tests/test_golden_payloads.py`: the 9 `twocaptcha-*` GOLDEN_CASES
    expected dicts gain `"softId": 5859`; the header comment updated;
    `test_referral_true_embeds_nothing_until_id_recorded` rewritten as
    `test_referral_true_embeds_project_soft_id` (asserts 5859); three
    default-adapter payload tests that were missed by the first pass were
    also updated (`twocaptcha-recaptcha-v3` golden case, v2
    proxy/worker-context, image extras + language pool, solve
    submit-then-poll round trip) — found by running the suite, not
    guessed.
- `CHANGELOG.md`: entry under `[Unreleased]` (user-facing behavior).
